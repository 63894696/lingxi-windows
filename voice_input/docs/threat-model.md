# Threat Model — `voice_input` 项目

> 与 ADR-001 配套的威胁模型。**自用场景**,假设威胁模型 = 「本机其他进程 + 网络其他主机 + 物理接触」三类。

## 1. 资产(我们要保护什么)

| 资产 | 敏感度 | 说明 |
|---|---|---|
| **音频字节流** | 高 | 你的语音,**最直接的隐私** |
| **ASR 输出的文本** | 中 | 取决于你在说什么 |
| **OI 提交给 TTS 的文本** | 低 | 通常是你 OI 给你的回复 |
| **presence_mode 状态** | 低 | 不算敏感,但**泄露模式=泄露你的工作流** |
| **auth_token** | 高 | 拿到它就能调 daemon(尽管 daemon 只在 loopback) |

## 2. 威胁源

| 威胁源 | 能力 | 动机 |
|---|---|---|
| **本机其他用户进程**(恶意软件、监控软件、广告 SDK) | 同 UID 读 `127.0.0.1` 端口 / 读文件系统 / 截屏 / 键盘记录 | 厂商行为统计 / 黑产 |
| **网络其他主机** | 监听 loopback 不可能,但**监听 0.0.0.0 上错误 bind 的 daemon 端口**可能 | 同上 |
| **物理接触者** | 直接看屏幕 / 拷贝文件 / 拔硬盘 | 取决于接触者 |

## 3. 威胁场景与缓解

### T-1:恶意软件读 `127.0.0.1` daemon 端口

**威胁**:同机恶意进程调 `POST /speak` 让 OI 说话 / 调 `POST /transcribe` 拿当前正在说的内容。

**缓解**:
- `auth_token` 鉴权(每次启动 daemon 生成新 token,文件权限 `0600`)。
- 文本注入**不通过 HTTP 触发**,而是通过 ASR daemon 内的物理热键直接触发——HTTP 路径不暴露文本注入能力。

**残余风险**:恶意软件如果读到 auth_token + 知道 API,**可以伪造 ASR 结果**——但**不能直接读你的麦克风**,因为恶意软件自己有麦克风采集能力,不需要通过我们。

### T-2:daemon 错误 bind 到 `0.0.0.0`

**威胁**:代码 bug 导致 daemon 监听所有网卡,网络其他主机可访问。

**缓解**:
- `config.py` 强制 `host = "127.0.0.1"`,代码层 `assert host in ("127.0.0.1", "localhost")`。
- `scripts/verify_offline.py` 启动后 `netstat` 验证所有 daemon 端口只 bind loopback。
- 文档明示「如果发现端口 bind 到 0.0.0.0,立刻报告」。

**残余风险**:用户手工改 config 强制 bind 到 `0.0.0.0`(绕过代码 assert)——这种情况**不在我们缓解范围,用户主动行为**。

### T-3:auth_token 文件被其他进程读

**威胁**:恶意软件读 `~/.voice_input/auth_token` 文件。

**缓解**:
- 文件权限 `0600`(Windows 用 ACL,仅当前用户)。
- auth_token 每次启动生成,过期(默认 7 天)。
- T-1 提到的缓解同样适用。

**残余风险**:Windows 上恶意软件以同用户身份运行 = 文件权限挡不住。这是 OS 层面的威胁,**不在我们缓解范围**。

### T-4:麦克风被同机其他进程抢

**威胁**:恶意软件也在采集麦克风。

**缓解**:**不是我们的责任**——OS 层面管理音频设备。如果用户想完全防,需要 OS 级麦克风权限管控(Windows 设置 → 麦克风 → 关掉不需要的 app)。

### T-5:屏幕内容被 OI 截取并上云

**威胁**:OI agent 调屏幕截图(已知能力,OI 0.4.x 有 `computer` 模块),把屏幕内容送给云端 LLM。

**缓解**:
- OI 进程是用户自己启动的,**用户在 OI 端配置 LLM endpoint**。
- `voice_input` 不主动调 OI 的截图能力,**OI 是否截图是 OI 自己的事**。
- **本项目的「隐私边界」只承诺到「我们不主动抓屏幕 + 不主动上传」**。OI 的行为超出我们承诺范围。

**残余风险**:OI 本身行为。这条**写明是用户责任**。

### T-6:物理接触者偷看

**威胁**:有人直接看你的屏幕 / 拷贝文件。

**缓解**:
- 项目无加密(自用场景没必要),但 `~/.voice_input/` 目录权限 `0700`。
- 物理安全是用户责任,不在我们承诺范围。

### T-7:模型文件被替换(供应链)

**威胁**:下载 SenseVoice Small 时被 MITM,或本地模型文件被恶意软件替换。

**缓解**:
- 模型下载源锁 `modelscope.cn` + `hf-mirror.com`,**禁止 git clone / 任意 URL**。
- 模型文件 SHA256 校验,**校验失败 → 拒绝加载**。
- 用户也可复用闪电说已下载的模型(`%AppData%\Shandianshuo\models\sensevoice-small\`),但同样需校验 SHA256。

**残余风险**:ModelScope / HF mirror 本身被攻击。这是上游风险,不在我们缓解范围。**会监测 ModelScope 公告**(若用户要求)。

### T-8:日志泄漏隐私

**威胁**:日志记录了完整文本 / 音频元数据,被其他进程读取。

**缓解**:
- 日志**默认不记录文本/音频完整内容**(`logging.log_request_bodies=False`)。
- 日志记录 IPC 摘要(请求路径、字节数、状态码),**不记录 body**。
- 用户**主动开启** `log_request_bodies=True` 时会有提示:「这会记录文本到本地日志,日志文件无加密」。

## 4. 不在威胁模型范围(显式声明)

- **OI agent 本身的行为**(截图、文件读、网络请求)**不在我们的威胁模型里**——这是 OI 的责任。
- **云端 LLM 的隐私**——用户决定 OI 用什么 LLM,云 LLM 怎么用他们的数据是他们的责任。
- **OS 级威胁**(键盘记录器、内核 rootkit、bootkit)**不在我们缓解范围**——需要 OS 级安全软件。
- **社会工程学**(诱导你装错版本)**不在我们缓解范围**——用户主动行为。

## 5. 触发再讨论的条件

| 触发 | 重新审视 |
|---|---|
| 用户在公共网络 / 公共电脑上跑此工具 | T-2 风险升级,需重新审视网络威胁 |
| 用户想给别人用 | T-3、T-6 风险升级,需重新设计 auth 和加密 |
| 发现 ModelScope / HF mirror 被攻击公告 | T-7 风险升级,需冻结模型下载 |
| 用户发现某个 daemon 端口 bind 到非 loopback | T-2 触发,需立即调查 + 修代码 |
