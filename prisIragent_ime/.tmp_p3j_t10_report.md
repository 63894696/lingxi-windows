## 6. Ctrl-C 退出日志

Ctrl-C 真触发路径已 code-complete(SetConsoleCtrlHandler → request_shutdown → 主循环下一轮 GetMessageW 收到 WM_QUIT 或 is_shutdown=true 直接 break):

```rust
// Ctrl-C handler
unsafe extern "system" fn handler(_ctrl_type: u32) -> windows::Win32::Foundation::BOOL {
    println!("\n[daemon] Ctrl-C received");
    request_shutdown();
    windows::Win32::Foundation::BOOL(1) // TRUE = 我处理了
}

// 主循环
loop {
    if is_shutdown() { break; }       // ← Ctrl-C 后这里 break
    let ret = unsafe { GetMessageW(&mut msg, None, 0, 0) };
    if ret.0 <= 0 { break; }
    ...
}

// 清理
WTSUnRegisterSessionNotification
DestroyWindow
UnregisterClassW
polling_thread.join()
```

清理日志预期:`message loop exited` → `WTSUnRegisterSessionNotification OK` → `window + class destroyed` → `polling thread joined` → `exited cleanly`。

注:开发机用 taskkill /F 验证架构切合度(WM_WTSSESSION_CHANGE 在单机开发机极少触发;真验 WTS_CONSOLE_CONNECT 等事件触发链路留 T9 VMware guest 端)。

## 9. daemon.rs 新设计要点

### 架构图

```
run_daemon()
  ├── SetConsoleCtrlHandler(Ctrl-C → request_shutdown)
  ├── CURRENT_DLL_PATH.set(config.dll_path)
  ├── RegisterClassExW("PrisirIMEMsg", WndProc)        atom=50147
  ├── CreateWindowExW(WS_EX_TOOLWINDOW, parent=HWND_MESSAGE)
  │                                                     hwnd=0x31d24
  ├── WTSRegisterSessionNotification(hwnd, NOTIFY_FOR_THIS_SESSION) ← 真注册
  ├── LoadLibraryA(dll_path)                            ← 初始 DLL 留引用
  ├── spawn mtime polling thread (5s,沿用 T5 简化)
  │       loop: sleep 5s → stat dll → mtime 变就 hot reload
  │
  └── 真消息循环:
          loop {
            if is_shutdown() break;                   ← Ctrl-C / WM_CLOSE 触发
            let ret = GetMessageW(&msg, None, 0, 0);
            if ret.0 <= 0 break;                      ← WM_QUIT 触发
            TranslateMessage(&msg);
            DispatchMessageW(&msg);                   ← 回调 wnd_proc
          }
      │
      └── 清理:
            WTSUnRegisterSessionNotification
            DestroyWindow
            UnregisterClassW
            polling_thread.join()
```

### WndProc 事件表

| msg                  | wparam (event)        | lparam (session id) | 动作                                              |
| -------------------- | --------------------- | ------------------- | ------------------------------------------------- |
| `WM_WTSSESSION_CHANGE` | `WTS_CONSOLE_CONNECT` (=1)   | session id   | 调 `register::do_register(CURRENT_DLL_PATH)`,真注册       |
| `WM_WTSSESSION_CHANGE` | `WTS_CONSOLE_DISCONNECT` (=2) | session id   | 调 `register::do_unregister()`,清注册                  |
| `WM_WTSSESSION_CHANGE` | `WTS_SESSION_LOGON` (=5)     | session id   | 仅打印日志(无人 connect 到 console 不动 register)        |
| `WM_WTSSESSION_CHANGE` | `WTS_SESSION_LOGOFF` (=6)    | session id   | 仅打印日志                                         |
| `WM_WTSSESSION_CHANGE` | `WTS_REMOTE_CONNECT` (=3)    | session id   | 仅打印日志(remote session 与 TSF register 路径独立) |
| `WM_WTSSESSION_CHANGE` | `WTS_REMOTE_DISCONNECT` (=4) | session id   | 仅打印日志                                         |
| `WM_WTSSESSION_CHANGE` | 其他                       | session id   | 打印 event 编号 + session id                       |
| `WM_DESTROY`         | —                     | —                   | `PostQuitMessage(0)`,触发主循环 break              |
| `WM_CLOSE`           | —                     | —                   | `request_shutdown()` + `DestroyWindow(hwnd)`      |
| 其他                   | —                     | —                   | `DefWindowProcW` 默认处理                          |

### CURRENT_DLL_PATH 共享机制

`wnd_proc` 处理 `WTS_CONSOLE_CONNECT` 时需要 dll 路径来调 `do_register`,用 `OnceLock<String>` 做进程级单次 set(在 `run_daemon()` 入口 set),WndProc 里 `.get()` 读。

理由: `wnd_proc` 是 `unsafe extern "system" fn`,不能捕获闭包变量(系统调用约定);又不能 `static mut` + 锁污染。每次 connect 一次性注册即可,不需要 mut。

### CreateWindowExW 参数

```rust
CreateWindowExW(
    WS_EX_TOOLWINDOW,                                   // 不在任务栏
    class_name,                                          // "PrisirIMEMsg"
    window_name,                                         // "PrisirIMEHidden"
    WINDOW_STYLE(0),                                     // 无 WS_OVERLAPPED 等
    0, 0, 0, 0,                                          // x, y, cx, cy 全 0
    HWND_MESSAGE,                                        // 父 = message-only
    None,                                                // hMenu
    hinstance_raw,                                       // 当前 exe instance
    None,                                                // lpParam
)
```

`HWND_MESSAGE = HWND(-3)` 是 Win32 保留值,表示"message-only window",只能收消息不能显示。

### WndProc 关键修复(对照 Win32 文档)

WM_WTSSESSION_CHANGE 的 wparam 是 **事件类型**(WTS_CONSOLE_CONNECT=1),lparam 是 **session id**(u32)。
原 spec 模板把 event 放在 `lparam.0` 是错的,已修正。

### T9 (VMware guest 端验证)

开发机(单 session、单用户、单 console)几乎不会自然触发 WM_WTSSESSION_CHANGE 的 WTS_CONSOLE_CONNECT 事件。
T9 需要在 VMware guest 里做:
1. 启 daemon(已具备 hidden HWND + WTS 注册能力)
2. 从 host 用 `mstsc` RDP 进 guest,触发 WTS_REMOTE_CONNECT 事件(确认 WndProc 真打日志 + 不污染 register)
3. 断开 RDP,触发 WTS_REMOTE_DISCONNECT
4. 在 guest console 上用 `query session` 切 session,触发 WTS_CONSOLE_CONNECT / DISCONNECT,验自动 register/unregister 真生效
